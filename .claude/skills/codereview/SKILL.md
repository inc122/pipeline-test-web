# codereview

Ревью только читает код. **Не редактируй никакие файлы** — исправления делает тот, кто вызвал ревью.

## 1. Определи, что ревьюить
- Если передан аргумент — это git-диапазон: `git diff <аргумент>`.
- Иначе — незакоммиченные изменения текущего шага: `git status --short` и `git diff HEAD`. Новые (untracked) файлы читай целиком.
- Шаг, к которому относятся изменения, — в `PLAN.md` со статусом `[~]`; его «Проверка» — эталон для тестов.
- Если изменений нет — так и напиши и закончи строкой `CODEREVIEW: PASS`.

Читай не только diff, но и изменённые файлы целиком: контекст нужен, чтобы понять, ломает ли правка соседний код.

## 2. Проверь
1. **Корректность.** Граничные случаи на входе: отсутствующий параметр, пустая строка, не число, `0`, отрицательные и дробные числа, `Infinity`/`NaN`, деление на ноль. Правильный HTTP-статус и тело ошибки.
2. **Правила `CLAUDE.md`.** Формат ответа арифметических эндпоинтов `{ a, b, result }`, CommonJS, маршруты в `src/app.js`, раннер `node --test`, нет лишних зависимостей.
3. **Тесты.** На новый эндпоинт есть тест; он проверяет данные из «Проверки» шага и хотя бы один ошибочный ввод.
4. **Согласованность.** Новый код ведёт себя так же, как существующий (валидация, формат ошибок).
5. **Простота.** Дублирование логики, мёртвый код — только как замечание, не блокирующее.

Запусти `npm test` — результат укажи в отчёте.

## 3. Отчёт
Выведи список замечаний, от самых серьёзных:

```
[BLOCKER|MAJOR|MINOR] файл:строка — что не так
  Сценарий: вход → фактический результат → ожидаемый
  Исправление: что поменять
```

- **BLOCKER** — неверный результат, падение, красные тесты, нарушение формата из `CLAUDE.md`, нет теста на новый эндпоинт.
- **MAJOR** — необработанный граничный случай с неправильным ответом.
- **MINOR** — стиль, дублирование, документация.

Сообщай только то, что можешь подтвердить кодом или запуском. Нет замечаний — так и напиши: `Замечаний нет`.

## Последняя строка (обязательно)
- `CODEREVIEW: PASS` — нет BLOCKER и MAJOR (MINOR допустимы).
- `CODEREVIEW: FAIL <K>` — есть BLOCKER/MAJOR, `K` — их количество.
