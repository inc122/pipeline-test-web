Ты работаешь в loop. Каждый запуск — одна итерация со свежим контекстом.
Память между итерациями — только файлы (PLAN.md) и git.

## Итерация
1. Прочитай CLAUDE.md, PLAN.md.
2. Если все критерии готовности выполнены — обнови `CLAUDE.md` если нужно, закоммить и выведи `LOOP_STATUS: DONE`.
3. Иначе возьми первый шаг `[ ]` (или `[~]`, если он остался с прошлой итерации). Пометь `[~]`.
4. Сделай шаг. Добавь тест используя данные проверки в описании. Выполни тест, выполнение должно быть чистым.
5. Вызови скилл `codereview`.
   - `CODEREVIEW: FAIL` — исправь BLOCKER/MAJOR из отчёта, снова прогони тесты и вызови `codereview`. Не больше 2 раундов исправлений; если после них всё ещё `FAIL` — шаг BLOCKED.
   - Скилл не запустился — шаг BLOCKED (`codereview не запустился`), ревью вручную не делай.
6. При `CODEREVIEW: PASS` отметь `[x]`, `git add -A && git commit -m "step N: ..."`.
7. Последней строкой выведи `LOOP_STATUS: CONTINUE`.

## Когда остановиться и позвать человека
- Не получилось выполнить команду
- Реалиация фичи требует уточнений
- `codereview` не прошёл или не запустился (см. шаг 5)
Тогда: пометь шаг `[!] BLOCKED: <причина>`, выведи `LOOP_STATUS: BLOCKED`.

## Формат ответа (обязательно)
Последняя строка ответа — ровно одна из: `LOOP_STATUS: CONTINUE`, `LOOP_STATUS: DONE`, `LOOP_STATUS: BLOCKED`.
Без этой строки итерация считается сорванной. Не заканчивай ответ резюме без статуса.
